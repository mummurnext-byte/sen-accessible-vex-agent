# Accessibility Standard

## Instruction Must Work Without Audio

A learner who mutes the video must still be able to:

- identify the lesson goal;
- follow the VEXcode Blocks stack;
- understand the robot's current state;
- complete the activity;
- answer the learning check.

## Visual Rules

- Use a minimum of 4.5:1 contrast for normal instructional text.
- Use large text and short labels in video.
- Pair every state color with a word, icon, or shape.
- Keep the same meaning for colors and icons across episodes.
- Highlight only the block currently being explained.
- Use arrows and numbers to show execution order.
- Avoid rapid flashing, decorative motion, and busy animated backgrounds.
- Leave the bottom 20% and platform-side overlays free of essential captions.

## Language Rules

- Use direct sentences with one action per step.
- Explain technical words before using them in a task.
- Keep official English VEXcode block names visible in both language versions.
- Translate meaning and classroom intent into Thai; do not translate block names into labels learners cannot find in VEXcode.
- Avoid idioms that do not translate clearly.

## Classroom Inclusion

- Give instructions in written and visual form before the robot starts moving.
- Use a visible countdown before motion.
- Provide visual turn-taking and team-role cards.
- Let learners replay the demonstration and inspect still frames.
- Use prediction cards and exit checks that can be answered without speech.
- Never require a learner to lip-read the digital host.

## Episode Audit

Before text approval:

- [ ] All narration meaning appears in captions or visuals.
- [ ] The objective is visible in the first 10 seconds.
- [ ] Block execution order is numbered.
- [ ] Color is never the only state indicator.
- [ ] English and Thai materials teach the same outcome.
- [ ] Technical terms are age-appropriate or explained.
- [ ] The activity can be completed without audio.

Before video approval:

- [ ] Captions are synchronized and readable.
- [ ] Essential content avoids platform overlay zones.
- [ ] Blocks remain legible on a phone screen.
- [ ] Robot behavior matches the approved text.
- [ ] Simulated or AI-generated shots are labeled.
- [ ] No unsafe hardware behavior is shown or encouraged.
